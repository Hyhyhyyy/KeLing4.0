## 结论与适用范围

**账号功能在可达网络下通过了真实注册、登录和跨端验证；当前 Vercel 域名在本次无代理网络下仍不能稳定连接，手机直连问题尚未完成解决。** 用户真实手机的错误文本、网络和版本尚未收到，因此本次复现不能代替用户设备复测。

电脑的 Windows 系统代理已启用。使用该网络的浏览器能够访问服务；Android 模拟器起初没有代理，使用同一域名登录超时。模拟器错误中域名被解析到 `2a03:2880:f12d:83:face:b00c:0:25de`，电脑直连 DNS 又得到 `104.244.43.182`，均非本次预期的 Vercel 服务入口；直连 HTTPS 请求超时。用于诊断的正确 Vercel 入口连接也被重置。现象支持“当前网络的域名解析与访问路径异常”，不能据此断言所有地区、运营商均不可用。

只给模拟器配置与电脑相同的可用代理后，**原服务、原账号、不改数据库**即可登录；手机表单新注册账号也能在网页登录。因此没有通过重置密码或修改用户账号来掩盖网络问题。模拟器代理仅用于对照测试，不是产品内置代理，也不代表用户真机直连已修好。

## 已修改内容

- Android 默认构建服务从仅模拟器可用的 `10.0.2.2` 改为现有公网 API，避免普通构建产生不能在真机连接的 APK。旧 4.0.1 已发布 APK 的内嵌地址经检查确为公网地址，因此此项是消除构建风险，不是对本次网络故障的单一解释。
- 登录、注册页面新增“连接检测与服务地址”：先检查 `/api/health` 的服务响应，再检查 `/api/ready` 的账号数据库连通性。检测不携带账号或密码；仅 HTTPS 地址可保存，拒绝用户名密码、查询参数、片段及非 API 路径。只有该次地址检测通过后才允许保存。
- Android 区分域名解析失败、超时、TLS 失败、密码错误和服务端错误，使用可操作的中文提示。错误密码的 401 不再被误标为“登录失效”。不暴露底层网络异常文本。
- Android 保存账号对应的服务地址，切换服务后不把旧会话当作新服务会话。邮箱统一去首尾空格和转小写，注册名字统一为 1–80 个字符，保留旧账号短密码的登录兼容，注册要求仍为 10–128 位。
- Web 增加网络失败提示和认证响应完整性检查；接口未返回有效 token 与用户身份时不进入登录状态。表单增加密码长度说明、输入约束、自动填充语义、提交期间禁用输入，以及可被读屏读取的错误提示。

调用路径：Android 表单 → `AuthViewModel` → `AuthRepository` → `AuthApi` → HTTPS 账号接口 → 原有数据库 → token 与账号身份存入 DataStore（Android 本机持久化存储）。Web 表单 → `useAppStore` → Axios 账号请求 → 同一接口 → 保存会话并读取 `/auth/me`。本次未改服务端密码算法、数据库结构或原用户账号。
