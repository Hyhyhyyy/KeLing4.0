# 主题知识星球

主题输入不局限于学校学科。可以输入网络用语、抽象概念或多义词，并补充已有基础、想了解的语境与目标。语境可选综合辨析、通识原义或网络文化。默认生成12题，也可选6题或18题。

## 从检索到可查看的星球

服务端先从联网搜索获取标题、网址、摘要和可用的时间信息，再将实际返回的资料编号交给模型。没有足够资料或检索不可用时停止生成，不用模型记忆冒充搜索。资料是搜索摘要，网页本身仍可能片面、过时或错误；“取得资料”不等于“事实已被证实”。

模型依据主题、基础和资料生成义项辨析、比较与边界，组织学习区域和练习，同时生成知识图谱。图谱节点数、分支数和层级按内容决定，层级关系与跨分支关联分开显示。节点可以查看摘要和对应来源，在确认创建星球之前即可浏览。为控制请求体与手机绘图规模，一颗星球最多48个节点、96条关系。

确认后，完整图谱保存在星球记录中；课程知识图谱还会得到同一批实际节点及层级关系。跨分支关联和关系标签保留在星球全图中，普通知识图谱编辑器仍沿用既有父子关系数据结构。

## 六种题型

支持单选、多选、判断、填空、排序和简答六类，按材料适用性组合，不强行凑齐每一类。6题至少3类，12或18题至少4类；缺少明确先后依据时不出排序题。单选与多选通常各有4至6个选项。判断题固定两个选项，填空接受列出的文字变体，排序比较完整顺序。简答先提交自己的表述，再对照参考答案及核对要点手动自核；系统不把这一步称为模型判分。客观题也只是与生成的参考答案比较，不构成经过教师审定的知识认证。

生成后先做结构检查，再由内容审核模型检查答案与解析、课文支持、来源边界和单位。审核器必须覆盖本次全部题目、区域与图谱节点，引用摘录必须实际存在；排序中的数值顺序另由代码核算。结构或内容有问题时最多修复一次，再复核；仍有问题则不签发可保存预览。自带模型Key时，生成、审核和修复都使用同一选定服务商。这个审核流程不是全学科正确性证明，也不能纠正所有来源本身的错误。

区域先修关系同时约束客观题完成和简答自核。修改上游题目后，下游完成状态会依据先修条件重新计算，其他题的作答仍保留。

## 对生成结果继续提要求

每道题可单独填写修改要求，例如“改成多选，增加一个常见混淆项”或“保留知识点，换成生活情境”。服务端只替换目标题并分配新的题号，保留其余题目与图谱，原题作答清除。生成失败、来源或答案格式校验失败时保留旧内容。保存后的修改按账号校验，并通过请求编号防止重复写入；另一个设备已改动内容时会要求刷新。

“相似碎片搜索”会围绕母题知识点重新联网检索，生成两道同题型的新情境练习。它们追加在本区域，不替换原题或清除原作答，也不让已完成区域重新锁定；基础区域完成仍由原来的基础练习决定。两题都经过结构与内容核对才一起写入，失败最多修复一组，仍失败保留原记录。每道补题保留自己的检索快照，防止新旧资料同名编号混淆。新材料的必要作答条件须在题面给足，不能要求用户凭隐藏来源猜答案。后续可以继续搜索或逐题重新生成；单区最多30道题，整颗星球内容仍受18万字符上限约束。

学习导航展示讲述文字、知识图谱和来源；进入探索练习后收起这些资料，避免将参考资料直接摆在答题旁边。用户随时可回看学习，补题的资料也在学习阶段可查。题内“问星芽”调用真实模型，带入当前题干、选项和本区讲解，优先提供分步提示，不默认发送答案、解析和评分字段。简答仍由用户对照要点自核，星芽提示不改动作答记录。

定制星球形象另走一条视觉检索链：联网查主题的外形或视觉结构，模型依据这些真实资料规划轮廓、地貌、细节及配色，选择形象来源页，再从实际网页中提取并验证参考图。有合法参考图时使用图生图，没有可用图片时仍依据检索到的视觉特征进行文字引导绘图。参考图网址只能来自真实网页，不能由模型编造；抓取限制页数、大小、时间和公网地址，重定向逐次核验。

角色主题须把原角色的轮廓、面部特征、体态和本色融入星球自身，不能只给通用星球加名字；学科和概念主题则将可解释的结构转译成地貌与建筑。用户仍可单独追加视觉要求重新生成。失败时显示默认星球或保留上一幅形象；不会把默认素材标成新生成图。形象是主题插画，不是事实依据。

## 代码入口与复现

生成入口是 `POST /api/learning/v1/planets/generate`，长任务返回编号，再查询 `generation-jobs/:id`。`topicResearch.ts` 整理实际搜索结果，`planetEnhancement.ts` 组织生成约束，`planets.ts` 校验并签署预览。`packages/shared/src/planet.ts` 负责两端一致的题型、来源、图谱和作答规则。预览修改使用 `regenerate-preview`，已保存星球使用 `/:id/regenerate`。

妙搭实例分别承担整星球结构化生成、单题结构化重生、内容审核、视觉规划、文生图和参考图生图，注册代码位于 `deploy/miaoda/server/modules/gateway/`。`planetReview.ts`验证审核覆盖及排序依据，`planetVisual.ts`组织视觉检索与设计，`visualReferences.ts`从真实网页读取图片。本地未配置真实搜索、模型或内容审核时应返回未连接错误；隔离测试里的合成返回只证明接口和状态规则，不证明真实模型效果。线上检索与实际生成结果另见对应日期的验证记录。
