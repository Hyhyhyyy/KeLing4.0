# 知识星图绘图引擎

2026-11-27，4.1.1-graph-rc2。

原星图自行计算节点与连线，排布和缩放效果难以统一。本轮嵌入 AntV X6 绘图引擎，使用 Dagre 计算知识点层级布局。X6 是程序可控制的图形编辑组件，不是外部网站或桌面软件的远程画面。课程仍由课灵管理，图形由同一份代码在两端绘制。

## 数据如何变成图

1. Web 或 Kotlin 请求当前课程知识点，取得名称、父节点、难度和保存位置。
2. 客户端只把绘图所需数据传入本地编辑器。账号令牌由宿主保存，不进入图形脚本。
3. `packages/graph-editor/src` 根据 `parentIds` 建立边，Dagre 计算初始层级，X6 绘制节点、连线及选中状态。
4. 已保存节点按统一 4096×4096 逻辑坐标还原。接口使用 0 到 1 的归一化位置，屏幕尺寸变化不会改变保存含义。
5. 用户可以拖动节点、缩放、查看全图或重新自动布局。修改首先保留在当前画布，按下“保存布局”才提交。
6. 宿主通过 `PUT /api/knowledge/:courseId/layout` 保存所有位置。每个节点同时带上读取时的 `updatedAt`，服务端在同一事务内检查版本并更新。冲突返回 409，失败不伪装为已保存。

Web 的入口在课程知识图谱页面，嵌入同源 iframe。Android 的入口在课程图谱页，嵌入本地 WebView；知识点的新增、编辑与删除继续使用原生界面。两端同源资源由 `scripts/build-graph-editor.cjs` 生成，生成副本不提交 Git。

## 保存标记的含义

一个节点的默认位置也可能是 `(0.5, 0.5)`，因此不能仅看坐标判断它是否保存过。服务端用内部课程布局记录保存坐标，读取时返回 `layoutSaved`、`savedNodeIds` 与 `layoutUpdatedAt`。新增节点或其他接口改变位置后，客户端能够识别需要再次排布与保存的部分。

内部布局记录不出现在用户笔记、统计或 AI 上下文中。课程删除时只清理该课程对应记录。不新增数据库字段，也不在发布时迁移生产数据。

## 构建与复现

```sh
npm ci
npm run graph:build
npm run graph:test
npm run test:web
npm test
npm run build:web
```

打开一门包含父子知识点的课程，自动布局后拖动一个节点并保存；退出重开，应恢复同一位置。再用第二个会话修改布局，第一会话用旧版本提交时应收到冲突提示。无网络或保存失败时，当前画布调整应保留，恢复连接后可重试。

锁定依赖为 `@antv/x6@3.1.8`、`@dagrejs/dagre@3.1.4`。脚本、样式和字体从应用自身加载；生产图形画布无需访问第三方 CDN。第三方许可随构建输出于 `graph-editor/licenses.json`。

## 依据与边界

- [AntV X6 官方介绍](https://x6.antv.antgroup.com/en/tutorial/about)：借鉴数据驱动节点、边及交互编辑方式，替代手写图形层。
- [Dagre 官方项目](https://github.com/dagrejs/dagre)：用于有向图的分层布局，适配知识点先后关系。
- X6 负责画图，不生成正确的学科知识。人工编排课程和模型生成课程的来源仍分别记录，模型内容仍需核对。
- 当前实现是知识图谱编辑器，不宣称具备完整工程制图、任意图形设计、自动教材审校或无限规模图形性能。

本轮实际运行、发布与设备验证见对应验证记录；上述复现方法不等于所有设备均已实测。
