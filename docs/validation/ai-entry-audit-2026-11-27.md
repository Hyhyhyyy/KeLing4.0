# AI 入口真实性核验与接入范围

时间：2026-11-27。本记录区分代码中真实模型调用、当前线上可用配置和已经完成的真实调用。配置存在、按钮可点、目录有模型均不等于调用成功。

## 公开 API 的当前事实

公开 API 已取得 **12 次实际模型生成结果**：RC2 的账号六种问答场景与资料导师 7 次，加上 RC3 的结构计划与复盘 2 次、三个游客入口 3 次。其中 11 项响应或完成事件明确记录妙搭提供方；快速问答只返回模型 ID，其妙搭来源依据受控调用链与 catalog 推断，缺少同次独立平台日志。RC3 版本为 `4.1.2-ai-rc3`（release `7712697456491809979`），当前默认规划已为 Miaoda。详见 [线上核验说明](native-ai-live-evidence-2026-11-27.md)、[七场景实际结果](native-ai-public-api-2026-11-27.json)、[计划闭环](native-ai-plan-public-api-2026-11-27.json) 和 [游客三个入口](native-ai-guest-public-api-2026-11-27.json)。

账号回答标明 `miaoda / miaoda-chat`，与当前资料快照持久化，第二次独立登录可以读取；其他账号读取被拒绝。概念解释经明确保存后成为 `AI_GENERATED` 笔记，问答没有自动创建任务。结构计划由用户确认后才创建任务，重复确认没有重复创建；复盘使用已完成任务状态，但预览没有新增任务。游客三路均为 202 加私有读取令牌的异步调用，无令牌或错误令牌读取返回 404。

历史上 RC2 完整脚本未全部通过：云端显式 `PLANNING_PROVIDER=agentarts` 使规划选旧工作流，脚本在规划调用前停止，所以七场景 JSON 的总状态仍保留 `FAILED`。RC3 改为 auto 后，计划和复盘已在独立报告通过，未篡改旧报告。首轮概念解释曾返回 `NATIVE_MODEL_FAILED`，没有获得回答；受控重试才获得七项结果。[首次调用失败](native-ai-release-7712689212100906275-failure.json) 单独保留，原因尚未独立证实，不能由重试成功推断永不失败。

本次服务没有提供 token 用量，证据中的 usage 为空；不估算为实际计费。没有默认向量嵌入模型，也不把关键词检索宣称为语义检索。其余个人 Key 厂商未逐一实测，不称全部可用。

## 通用桥接前的历史状态

只读请求证据见 [接入通用模型前的实际响应](ai-availability-before-bridge-2026-11-27.json)。账号通用助手 `/api/ai/catalog` 的 14 项服务均未配置；公共试用不可用、游客工作区模型目录为空。学习星球目录已有 `miaoda-learning`，真实生成证据另见 [原生模型调用](planet-native-model-2026-11-27.json) 和 [历史星球公开 API 验收](planet-history-public-api-2026-11-27.json)。

当时 `/api/agent/status` 返回 `configured: true, provider: AgentArts`。该状态仅来自环境配置项是否存在，单看状态不能证明真实调用。随后用专用测试账号的课程资料实际发起一次规划，66.995 秒后返回 `SUCCEEDED`，获得 1 个符合来源、日期与每日 20 分钟预算的任务；未确认任务。已存 [实际工作流结果](ai-planner-before-bridge-2026-11-27.json)，它修正了 11 月 26 日 HTTP 403 的历史状态。返回事件只有资料检索和工作流开始/结束，没有明确模型节点，故结论限于“工作流调用成功，内部模型调用尚未独立核实”。调用链没有固定计划回退逻辑。通用问答缺少默认模型是桥接前的缺口，不能再当作当前目录状态。

| 用户入口 | 服务端实现 | 实际行为及当前边界 |
| --- | --- | --- |

| 从笔记、课程、任务或示例题打开 AI | `ai/context.ts` → 上述会话路径 | 先解析当前账号来源和版本；确认后才调用模型。来源预览本身是数据库读取，不是 AI。 |
| 游客问答与计划 | `ai/guest.ts` → `complete` | 公共问答与纯导入资料计划均完成真实调用；响应含妙搭 providerId，异步任务读取隔离通过。计划校验日期、时间预算、真实来源 ID。个人 Key 厂商未在这次试验逐一实测。 |
| 临时个人 Key 问答 | `ai/modelAccess.ts` → `credentialProvider` → `complete` | 真正转发到用户选定的官方服务；不保存密钥，不改换厂商。不代表所列全部厂商均有本次可用性证据。 |
| 公共快速问答 | `ai/trial.ts` → `complete` | RC3 已完成实际调用与令牌隔离。响应有 model: miaoda-chat，但没有 providerId；本次未找到独立平台完成日志，只能结合原生 catalog 与受控调用链推断来源，不伪称响应直接包含提供方或已有同次日志匹配。 |
| 资料导师 | `learning/routes.ts` 的 `tutor` → `complete` | 无个人 Key 的公共妙搭调用已成功，也保留个人 Key 路径。答案前后检查资料版本，检查引用编号；引用编号有效不等于语义准确。 |
| AI 计划与复盘编排 | `agentarts/routes.ts` → `AgentService` → 妙搭、DeepSeek 或 AgentArts | RC3 默认妙搭的计划、确认入库、重复确认和复盘已通过真实验收，并有模型开始/完成事件。显式厂商不偷偷回退。AgentArts 另有工作流成功结果，内部模型节点仍待原账号核实。 |

| 语义检索 | `ai/retrieval.ts` → `transport.embed` → 向量相似度 | 只有显式启用向量模型时才调用真实嵌入服务。当前无默认向量模型；不能把关键词检索标成已实现的语义理解。 |
| 模型发现 | `modelAccess.discoverAccess`、`transport.discover` | 查询服务商目录，不生成学习内容；目录可见不等于账户有权限或额度。 |

## 本轮实施方案

复用已真实验证的妙搭 CapabilityService，由可信部署适配层注册通用文本模型，主服务只接受受控 `messages` 与输出上限。注册后才能公开 `miaoda-chat` 目录；来源标明妙搭，不命名为华为。账号会话沿用已有异步 turn，规划沿用异步 AgentRun；游客及资料导师的原生调用需要短请求返回 job 后轮询，避免网关超时。

个人 Key 路径保持厂商选择与失败语义，不偷偷回退公共服务。向量检索没有对应嵌入能力时保持不可用。规则计算维持准确名称，不为了宣称“全 AI”而加入无必要的模型调用。

主服务与部署适配层已实现上述桥接和 HTTP 契约，十二项公开 API 调用已取得真实模型结果，包括计划和复盘的生产闭环。本地合成回调测试只验证程序行为，不充当外部模型调用证据。

## 主服务实现及回归

- `ai/native.ts` 导出 `registerNativeAiBridge` 与请求/响应类型。消息仅为 `role/content`；计划与复盘传 `purpose: study-plan` 供可信适配层选用官方结构化插件；普通聊天不传 purpose。注册才开放 `miaoda / miaoda-chat`，游客目录维持 `public / miaoda-chat`。不把原生服务加入个人 Key 厂商列表，不宣称提供向量模型。
- `transport.complete` 分派至可信注册函数；无有效输出、服务失败、取消或超时均失败，不返回示例内容。只保留服务确实报告的用量，不推算 token 数。
- `ai/jobs.ts` 使用现有 AgentRun 保存临时结果，默认 3 分钟过期、后续请求清理 24 小时前记录。账号按身份、游客按随机读取令牌隔离；令牌仅存哈希。请求输入和个人 Key 不写入 job，个人 Key 原有同步路径不变。
- 原生游客问答、计划、快速问答和账号资料导师返回 202；`GET /api/ai-jobs/:id` 返回 RUNNING / SUCCEEDED+result / FAILED+code+error。游客使用 `X-AI-Job-Token`，账号使用 Bearer。停止等待不宣称远端调用已取消。
- 账号通用对话沿用已有异步 turn。账号规划的默认 auto 优先已注册妙搭；显式指定 AgentArts/DeepSeek 时绝不偷偷换厂商。妙搭规划调用事件记录实际 providerId/modelId，结构输出通过原有来源、日期、预算校验后才可确认。
- 资料导师默认可使用公共模型，也可显式选择已启用服务或个人 Key；资料仍须属于当前账号课程，生成后再次检查来源版本及引用编号。

`npm test` 包含 TypeScript 构建，107/107 通过。新增 4 项测试以明确的合成回调验证桥接、结构 purpose、公共可用性、失败与取消、无向量能力、任务读取隔离、迟到结果不能复活、实际 HTTP 会话/导师/计划及确认入库。它们不证明外部模型真实调用；外部模型和线上验收须独立记录。

## 普通学科与二叉树示例隔离

实际端侧检查发现旧示例页面会对任意非 AI_PLANET 课程调用二叉树章节接口，服务端随即创建空进度和 SEED 讲义，可能让普通英语课程的 AI 引用不相干资料。本轮用 `expedition/courseAccess.ts` 统一隔离：明确的 SAMPLE 标记（兼容 BINARY_TREE_SAMPLE）或真实旧练习历史才可载入示例，AI_PLANET 始终排除。课程名称不参与判断；只有旧 GET 留下的空进度不算学习历史。

课程列表与详情新增 `hasBinaryTreeHistory`。历史判据为真实 run 或非空练习记录、证据、复习安排、星芽自述；前端仅在明确示例入口创建 SAMPLE 课程。后端章节读取和开始练习也独立检查，普通课程返回 `409 / SAMPLE_REQUIRED`，事务不会新增示例资料或进度。

对旧页面误加的 SEED，普通学科材料列表、直接资料读取、助手上下文、检索和规划来源均排除；原数据库记录仍保留。真正学习过示例的旧课程继续读到原有材料与进度。未执行全局数据删除或迁移。

加入该修复后最终 `npm test` 为 **108/108 通过**，包含 TypeScript 构建。新增 `example-isolation.test.cjs` 实际 HTTP 验证普通课程和 AI_PLANET 拒绝示例初始化、无部分种入；旧空进度不提升资格；错误资料被来源链排除但原记录保留；明确示例和真实旧练习仍可继续。原二叉树测试夹具改为明确 SAMPLE，不再依赖任意课程自动初始化。
