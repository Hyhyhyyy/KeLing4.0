# 个人形象与成就家园 服务端验证

2026-11-27。本记录对应本轮新增 Journey 服务，不把临时数据库中的合成记录当成真实学习时长或线上达成证据。

## 数据与调用链

`packages/shared/src/journey.ts` 定义10个头像、10个头像框、10块称号牌、10件家具及10个对应成就。`journey-catalog.json` 是 Android 离线目录，测试逐字段核对其与 TypeScript 目录一致。头像可直接选择，框、称号、家具需满足相应成就。第一个条件是创建知识星球，最后一个是累计记录6000分钟（100小时），中间包含任务、笔记、知识点、累计打卡及60/600分钟里程碑。

公开目录为 `GET /api/journey/catalog`。账号请求带既有 Bearer 登录令牌：

- `GET /api/journey/profile` 读取当前事实、已解锁奖励、装扮与10个家具陈列位置。
- `PATCH /api/journey/profile` 接收 `expectedRevision` 及选填 `avatarId`、`frameId`、`titleId`、`furnitureSlots`。只有已拥有的框、称号、家具可以保存，同件家具只能陈列一次。旧端数据版本返回409，失败不覆盖先前装扮。
- `GET /api/journey/calendar?month=YYYY-MM` 返回上海时区每天的打卡、已记录学习分钟、完成任务和普通笔记数量。

装扮使用单一 `JOURNEY_PROFILE_INTERNAL` 内部记录，并复用现有用户行锁与事务。未修改数据库结构或迁移生产数据。内部记录已加入统一排除清单，不出现在普通笔记、笔记数量、关键词检索、AI上下文或规划资料中。旧头像 `stellar:avatar-0..8` 保留，新目录使用 `journey:avatar-0..9`。

成就由账号实际持久化记录计算，客户端不能提交已解锁列表。GET读取时保存首次观察到的达标成就；已解锁装饰不会因后来删除笔记或课程而收回。未发放新经验、结晶或学习掌握认证，也不以家具奖励替代教学评价。旧基地购买数据保留，新家园不用购买。

## 时间与日历的含义

累计分钟取现有 `User.totalStudyMinutes`，它是用户提交并成功保存的学习记录，包含任务完成、课程记录与学习自述，不能称为独立验证的专注时长。任务计时仍通过现有完成接口保存实际分钟。新任务未提交 `actualMinutes` 时只标记完成、记0分钟，不再把预计时长当成已学习时长；显式提交的分钟仍可保存，重复完成不能重复增加。旧历史累计不回写。

日历取任务的 `completedAt / actualMinutes` 和不关联任务的 `StudyRecord`；已关联任务的镜像记录不重复计时。未来课程学习时长提交也在同一事务内产生 `SELF_REPORTED_COURSE` 记录。历史只有累计数而没有日期的分钟不会被编造到某一天，因而日历月总计不一定等于全账户历史累计数。月份范围2000—2100，日期按 Asia/Shanghai 处理，月初月末没有UTC偏移一天的问题。

## 验证结果

初轮 `npm test` 在独立临时 SQLite 数据库内运行，114项通过。修复未计时完成的默认分钟后，最终全套 **115项通过，0失败**，包含原108项回归与新增7组 Journey 检验。服务端与共享库编译通过。

最终复测时本机演示服务占用了 Prisma Windows DLL，`prisma generate` 无法重命名文件。未停止演示服务；核对已生成SQLite schema与源码在去除格式空白和注释后完全一致，复用现有客户端，并按原测试入口执行共享库构建、服务端编译、新建独立临时库及三份SQL初始化、全部测试。复测日志为本机 `.cache/journey-server-tests-final.log`，没有运行应用库或线上库迁移。

新增检验覆盖目录数量和奖励一一对应、5999/6000分钟边界、空账号与锁定奖励拒绝、同一次成就不重复创建状态、另一个数据库客户端读取装扮、版本冲突不覆盖、家具去重、其他账号隔离、上海月份边界与闰年、内部记录排除、严格请求字段以及真实任务完成服务的重复提交。另验证预计120分钟的任务缺省完成仍记0，显式提交1分钟后再提交99分钟仍累计1分钟，任务数与日历分别正确。HTTP测试确认新的课程记录确实进入日历。

第一次测试中3项失败来自测试夹具遗漏任务必填 `description` 及把既有课程POST接口写成PUT，修正夹具后全套通过。测试不调用任何外部模型，没有对线上账号、日历或100小时成就写入假进度。
