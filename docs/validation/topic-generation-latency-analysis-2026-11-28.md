# 学习星球生成耗时分析与无损优化边界

本分析读取已有真实调用证据及当前部署适配器、官方 SDK 源码，没有新模型请求，没有修改学习生成管线。分析基线为主仓 `debf497` / 模板 `91c5aa9`；后续优化效果须用新的实际请求另外测量。

## 已有事实

| 已观察环节 | 实际耗时 | 证据与解释 |
| --- | ---: | --- |
| 默认6题的两轮课程生成 | 39.849秒、38.511秒 | [最终默认入口](topic-final-default-content-2026-11-28.json)，内容修复重写整份课程，最终仍因答案与解释冲突拒绝保存 |
| 同次后两轮内容审核 | 5.875秒、3.887秒 | 同上；本次末次失败不是审核超时 |
| 曾出现的慢审核 | 89.312秒 | [线上诊断](topic-online-diagnostics-2026-11-28.json)，说明不能由少量快样本推导审核总是很快 |
| 本地真实视觉检索、设计和抓参考图 | 合计14.039秒 | [视觉链](topic-visual-chain-real-2026-11-28.json)，该证据未细拆三者，不能独自归因于检索或网页抓取 |
| 同次真实绘图 | 32.388秒 | 同上，总链46.428秒；图像是否满足设计还须人工看图 |
| 已有真实单题再生 | 12.42秒 | [真实功能证据](topic-live-evidence-2026-11-28.json)，它与整份重写不是同一输入，不能直接作为提速承诺 |

`topicResearch.ts` 已用 `Promise.allSettled` 并发两条查询，并按排名交错合并；再包一层并发不会使这部分更快。官方 `@lark-apaas/nestjs-capability` 的 `load()` 从本地 `Map` 取配置，插件实例和manifest也已有缓存，缓存执行器本身不是主要优化方向。

官方 `ai-text-to-json@1.0.26` 虽在插件内部读取 SSE 文本，但对调用方暴露的是 unary action；公开 `callStream()` 对这种action只有最终一次yield，并非可用的逐token进度。SDK `PluginActionContext` 没有取消信号字段。现有原生服务在调用前后检查取消状态，但不能据此宣称底层付费请求已经被中止，也不应通过修改私有SDK虚构取消或流式能力。

## 优先建议

1. 初稿通过结构检查后，让内容审核与视觉资料检索、设计、参考图准备重叠进行。审核通过后才正式绘图。若修复改变 `subject/meaning/goal` 等视觉依据，必须丢弃或重算旧准备结果；最终确认仍等待完整审核与图像流程。理论收益仅是两个分支的重叠部分，不能预先承诺固定节省秒数。
2. 精简送审副本中的重复材料与无关元数据。单题范围已将局部 `practiceResearch` 复制到顶层 `research`，但仍携带原副本、旧图像提示与网址、生成元数据。对一份已有真实通过样本离线计算：输入21,775字节；删除重复局部research后15,489字节；再删 `id/generatedBy/reviewStatus/planetStyleIndex/artwork` 后12,070字节，减少44.6%。完整10条原始来源摘录、课文、题目、所有答案与解释、meaning/title/story均保留。只能改送审投影；严格验证仍使用原始草稿。整星球范围不能随意删除每题不同的局部research。
3. 当整份审核只指出少数题目问题时，可只生成这些题的修复，再确定性合并并重新审核全星球。保留原课文、图谱和其它题目字节；涉及课文、来源、图谱或整体结构的问题不能套用此捷径。这样减少重复输出，不减少审核范围。
4. 两道相似题的单题审核可在同一次生成后并发，保持每题原有范围、来源域和严格校验，汇总后仍只使用既有修复预算。需观察真实并发尾延迟，不应假设平台无限并发；生产验证继续由主线程统筹串行触发。
5. 同页独立参考图候选可限制为最多两个并发验证，并按原始候选顺序收敛。继续检查每跳DNS、固定连接IP、超时、大小、MIME和实际字节；继续保留总2页、2图和20秒边界。不要直接并发占满两页额度而破坏404/410同源主页回退。

## 缓存与展示边界

优先复用同一个作业内、主题与语义未变化的视觉准备结果，以及当前修复已取得的真实资料。不把跨用户模型结果直接复用，不将旧搜索缓存标为本次实时检索，不缓存错误以代替新请求。跨作业网页缓存应有来源URL、抓取时间、大小上限、正常过期和重新验证机制；它不是当前主要耗时，未验证收益前不增加长期复杂度。

后台应在真实进入检索、生成、结构检查、审核、修复、视觉检索、设计、参考图、绘图、封装时更新阶段。前端动画可持续运行，但只能说明仍在处理当前阶段；模型没有提供完成比例时，不能将时间插值包装成真实百分比。全部后台条件完成后才显示100%。游戏提示语应描述当前动作，不泄露答案、内部提示词或未验证内容。

模型、来源数量与原始摘录、生成题量、图像分辨率、审核规则和修复上限均不因提速而降低。以上为具体优化建议与已有证据，尚不是新版本速度测试结论。
