# 网页文字系统调整 · 2026-10-29

本轮针对用户提出的“全面美化网页端和移动端所有字体”。本文记录网页部分；Android 的实际构建与设备检查由移动端工作目录单独记录。

## 为什么调整

原页面混用了 10–11 px 标签、多种偏浅灰色和不同标题字号。部分任务状态、掌握度数字直接使用浅色主题色，白底下不够清楚；深色页面又可能继承其他页面的深色文字。本轮保留星际插画、页面内容和数据行为，把文字统一成标题、正文、辅助、操作、数字和状态六种角色。

公开参考：[Todoist 功能页](https://www.todoist.com/features)、[TickTick 功能页](https://ticktick.com/features)，查阅日期 2026-10-29。参考的是其对任务、优先级、说明和统计的分组思路；下面的具体字号、字重和颜色为课灵自行设计，未复制竞品字体文件，也未声称测得竞品内部样式。检查依据还包括 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 对可读性、缩放与数字排版的要求。

## 文字如何分工

|角色|字号与字重|颜色与用途|
|---|---|---|
|页面标题|26–32 px，700；首页展示标题最高 38 px|海军蓝 `#14263D`；深色背景使用奶油白|
|区块与卡片标题|16–21 px，600–700|突出任务名、课程名和下一步操作|
|正文与长内容|14–16 px，400，1.75–1.9 倍行高|深灰绿 `#34483F`；输入和 AI 长文不整段加粗|
|辅助说明、时间、标签|12–14 px，400–600|`#52675F` / `#607168`，保持可读性|
|操作与状态|13–15 px，600–700|深绿强调；成功深绿、提醒棕色、错误红色，同时保留文字标签|
|统计与计时|主要数字 27–30 px，700|使用等宽数字特性，使位数变化时更稳定；单位较小|

字体采用本地无衬线字体栈，中文优先适配苹方、微软雅黑、Noto Sans；无需下载外部字体。此次 Windows Chrome 实际使用 **Microsoft YaHei Regular（正文 400）** 和 **Microsoft YaHei Bold（标题 700）**，已通过 Chrome 的实际字形来源接口核对。不同系统会采用各自可用字体，不能保证字形完全相同。

深色首页、报告、成就、个人卡和课程头部分别指定浅色文字。个人卡改为深绿底；课程头部保留课程色并增加深色遮罩，避免任意浅色课程主题导致白字难读。手机宽度的任务操作移到文字下方，课程、时长和状态可自然换行；笔记列表在大字时保持控件高度，通过列表自身滚动浏览。

## 修改入口

- `apps/web/src/styles/typography.css`：统一字号、字重、行高、语义颜色、深色表面及窄屏适配。使用 `#root` 作用域，以免按需加载的旧页面样式重新覆盖文字规范。
- `apps/web/src/App.tsx`：在原主题后引入上述样式。
- `apps/web/src/pages/Tasks/Tasks.tsx`：四种状态由浅色硬编码改为语义颜色变量。
- `apps/web/src/pages/Greenhouse/CourseDetail.tsx`：掌握度数字移除浅色课程主题内联颜色，由统一数字样式控制。

修改不改变注册、登录、任务写入和 AI 调用逻辑。字色只能强化已有状态含义，不能代替状态文字。

## 实际验证与边界

- TypeScript / Vite 构建通过。ESLint 为 **0 错误、38 个已有警告**；没有把警告解释为全部代码无问题。
- Chrome 逐页检查登录、注册、介绍、首页、课程列表、课程详情、任务、笔记、AI 助手、智能编排、个人中心、成就、报告、设置、知识图谱、图鉴，共 **16 个页面 × 1440 / 390 / 360 px = 48 个页面状态**。每次截图断言目标 URL，并核对页面标题，避免把跳转登录或网络错误当作页面成功。
- 48 个状态均无页面级横向溢出，检查到的可见文字均不小于 12 px，未记录 JavaScript 页面错误。导航、任务筛选和笔记列表自身的滚动仍然保留。
- 在 390 px 宽度，对首页、任务、AI 助手、笔记、注册分别将文字放大至 **130% 和 200%**，共 10 个状态。通过浏览器内逐元素调整实际文字尺寸进行压力检查，10 个状态无页面级横向溢出。它是文字放大检查，并不等于所有浏览器的原生缩放或读屏验收。
- 按标准相对亮度公式计算设计颜色组合：标题/纸色 14.90:1，正文/纸色 9.55:1，辅助/纸色 5.91:1，弱化文字/纸色 5.05:1，操作绿/纸色 7.77:1；成功、提醒、错误各自浅色底为 6.19:1、6.07:1、5.74:1。这是列出的颜色组合结果，未声称所有透明叠层、图片区域和禁用状态都完成逐像素审核。

浏览器使用本地 Vite 与 **3003 端口的隔离 SQLite API**，只创建合成测试账户、课程、任务和笔记。首次真实读取后的 GET 响应在截图上下文内复用，防止几十次页面刷新耗尽本地鉴权限流。这些截图验证 UI，不代表本轮已验证公网认证或真实模型调用；没有调用付费模型或使用生产用户资料。

最初检查曾因本地限流得到错误页，又发现首次首页截图可能在注入测试令牌前跳到登录。最终脚本改为文档初始化时设置隔离测试账户令牌，并加入 URL / 标题断言。最终证据已替换这些无效截图。长页面截图会先等待懒加载图像解码，避免把未滚入视口的占位背景当作完整页面。
