# 学习报告统计与标注修正

> 历史记录（2026 年 10 月）。保留当时版本、操作和验证结论；当前入口与运行方式见[文档索引](../../README.md)。

日期：2026-10-29。范围仅为 Web `StudyReport.tsx` / `StudyReport.css`，未修改数据库、共享 API 或 Android。本记录是实现与验收说明，不能作为真实 AI 复盘已经实现的证明。

## 问题与依据

原页面的 `generateAIInsight` 是固定规则拼接，却显示为“AI 洞察”“AI 建议”；没有完成任务也会评价“保持了良好的学习节奏”“没有明显薄弱领域”。这些表述缺乏测评证据。

原页面把所有课程的 `totalStudyMinutes` 相加，显示为“本周学习”。实际 `apps/server/src/controllers/courses.ts` 的掌握度更新和 `services/taskCompletion.ts` 都累加该字段，它不是按周划分的记录。

`services/taskCompletion.ts` 在完成任务请求未提供时长时，会把 `estimatedMinutes` 写入 `actualMinutes`。因此即使客户端字段名叫 actualMinutes，也不能把所有历史值描述为独立计时测量。当前数据没有记录该值的来源，无法反推它是手动确认、默认时长还是计时结果。

`services/checkin.ts` 更新的 `streakDays` 是最近签到时保存的连签长度，不是知识掌握证据，也不能单独证明截至今天仍在连续学习。

## 改动

- 改为“记录摘要”和“下一步可尝试”，明确是依据记录的规则整理，未调用 AI 模型；删除无证据的优势/薄弱和效率结论。
- 采用明确的滚动 7 天窗口，按 `completedAt` 统计已完成任务，包含窗口两端，排除未来、无效或缺失完成时间。界面以北京时间显示精确到分钟的范围，不再称自然周。
- 分别展示近 7 天任务记录时长、完成数、独立的最近签到连签记录，以及当前课程的累计时长。任务时长缺失不使用预计值补齐，0 分钟视为已记录；缺失数量单列。
- 课程掌握度仅称为“当前记录值”，不计算缺乏来源说明的平均测评结果；默认 0 无法区分未填写和未掌握时如实说明。
- 页面独立读取 `/auth/me`、`/courses`、`/tasks`；任一请求失败则显示错误与重试，不把加载失败解释为零数据。快照绑定账户，切换账户不会显示上一账户统计。用户切回窗口或点击刷新时更新快照。
- 用纯函数汇总一次成功读取的快照；删除重复模拟加载、提前调用未初始化函数和渲染中读取当前时间的行为。
- 加入档案室场景和双栏记录区域；样式限定到报告容器，避免原先通用 `.page-header`、`.stat-box` 等规则污染其他页面。

## 实际验证

1. `npx eslint src/pages/StudyReport/StudyReport.tsx`：退出码 0，无警告或错误。
2. 在 `apps/web` 运行 `npx tsc -b`：退出码 0。主线程负责最后的全量 Web 构建、浏览器与部署验收。
3. 用 TypeScript 将当前文件的 `buildReport` 纯函数编译后，在 Node VM 中执行以下五组断言，全部通过；未写入数据库，未调用模型：

|检验对象|输入/边界|观察结果|
|---|---|---|
|没有证据|空课程、空任务|0 项完成、0 分钟，摘要明确证据不足，无肯定诊断|
|时间窗口|恰好位于起止点；起点前 1 秒；未来 1 秒；无效/缺失时间|仅起止点 2 项计入，共 50 分钟|
|缺失与零值|null 时长且预计 240；0 分钟；12 分钟|3 项完成，记录时长 12，缺失 1；没有把预计 240 加入|
|累计分离|课程累计 900；近 7 天任务 15|分别保留 900 与 15，不混为周学习时长；掌握度标明非测评|
|任务状态|PENDING、IN_PROGRESS、ABANDONED|当前待办 2，完成数 0|

统计检查从当前源文件中截取 `interface StudyReportData` 至 `const dateFormatter`，通过工作区 `typescript.transpileModule` 编译，然后执行 `buildReport(user, courses, tasks, new Date('2026-10-29T14:00:00Z'))`；使用 `node:assert/strict` 核对上表。时间作为显式输入，复现不依赖运行日期。
